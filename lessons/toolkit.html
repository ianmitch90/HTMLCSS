TOOLS & SYSTEMS / YOUR OWN PATH

Do I have to build everything from scratch?

No. HTML and CSS are the foundation; libraries and design systems can take care of repetitive work. Learn what each one gives you, what remains your responsibility, and when the simplest tool is best.

For curious newcomersDeeper developer notesNo installations

The web is collaborative, even when you work alone.

Knowing HTML and CSS is like knowing cooking techniques. You can make something original, diagnose problems, and understand what a recipe does. But kitchens still use reliable equipment, repeatable procedures and familiar tools. Web libraries package repeated decisions about layout, color, spacing, accessibility and interaction so you can reuse them.

Some packages offer only focused utilities; some supply an entire set of visual components; some implement a company's design language. Others help with underlying behavior but leave appearance to you. None eliminates the need to understand what your page does for a real person.

Two tracks, no prerequisite exam

Just curious? Skim the examples and learn the vocabulary. You do not need to install or master these tools. Building software? Follow the source links and decision checklist to make deliberate, maintainable choices.

Start with the browser.

A three-page portfolio might need only HTML, CSS and perhaps a small JavaScript enhancement. Native controls such as <details>, <dialog> and form validation already handle much of what older libraries implemented by hand.

Bootstrap: a ready-made toolkit.

Bootstrap provides a mobile-first grid, utilities, components and optional JavaScript plugins. It is practical for directly linked static HTML pages. Modern Bootstrap dropped the mandatory jQuery dependency of earlier versions. It provides conventions, not a guarantee that your final content, colors and interaction flows are accessible.

Visit the Bootstrap-origin exhibit ↗ · Try actual Bootstrap 5 on a separate page ↗

Tailwind: compose your own visual language.

Tailwind gives you utilities for spacing, typography, color, borders and layout rather than one required default-looking button. It generally compiles classes into an output CSS file during development or deployment. Tailwind's Play CDN is for development, not production. Static HTML can still use the compiled output: you don't need a browser-side React app to use Tailwind.

Where does jQuery fit?

jQuery solved significant cross-browser DOM and event-handling problems and remains relevant for maintaining older websites and plugins. It has a supported 4.x line, but many common tasks now have straightforward native JavaScript equivalents such as querySelector(), addEventListener() and fetch(). New sites do not automatically need it; older sites should plan for upgrade compatibility instead of assuming it will never change.

A library and a design system aren't the same thing.

A design system is an organization's language and practice: tokens, accessibility standards, interaction rules, documentation, content guidance and governance. A component library is a code implementation that may express parts of that language. Sometimes the same organization publishes several implementations.

Google Material Design / MUI

Material Design is a design language; Material UI is an open-source React library implementing a Material approach. Adopting MUI typically requires a React project rather than a bare HTML file.

Material Design ↗ · Material UI ↗

Microsoft Fluent

Fluent is a cross-platform design language. Fluent UI offers implementations including React components and Web Components. The specific package matters, even when the visual design language is shared.

Fluent design ↗ · Libraries ↗

IBM Carbon / Adobe Spectrum

These enterprise systems show how teams coordinate accessible UI, patterns, tokens and writing guidance across products. Their documentation is worth studying even when you build with different tools.

Carbon ↗ · Spectrum ↗

Headless and platform-independent UI

Radix Primitives and React Aria help React developers with complex interactions, focus and keyboard support while leaving visual choices to the product. Web Component libraries offer reusable custom elements that can fit into many framework environments.

Radix ↗ · React Aria ↗ · Web Awesome ↗

Smaller libraries and community components

Alpine.js and htmx can be useful for particular HTML-first interaction styles, while curated visual libraries such as 21st.dev offer design inspiration and component code. Treat these as situational options with changing APIs, packages and maintenance expectations—not permanent defaults. Review license terms, runtime dependencies, source quality, focus handling, reduced-motion behavior and rendering costs before using a snippet.

Reusing components helps—but doesn't certify the result.

A tested component might manage keyboard navigation, focus restoration, and state announcements that would be tedious and error-prone to implement independently. That is a compelling reason to use good libraries. Your actual page still owns the content, labels, contrast, error recovery, sensible visual/source order and end-to-end testing.

A CSS toolkit usually has a different JavaScript cost from a rich React component library. A generated Tailwind CSS file has a different runtime model from the development-only browser CDN. Performance depends on how the library is built and used, not simply how famous it is.

“Well-maintained” is never “maintenance-free.”

Prefer official documentation, clear release practices, security policies, accessible examples, manageable dependency trees and portability. Budget for upgrades and verify accessibility claims at the component and application level.

Choose by the actual project.

I'm casually exploring.

Start with plain HTML/CSS and these lessons. Use an existing template when it helps you learn, not as something you must memorize.

I need a simple site quickly.

Use static HTML and a small design system—or Bootstrap if its responsive components and conventions suit the job.

I'm already building React.

Compare a styled system (MUI, Fluent), an unstyled interaction foundation (Radix, React Aria) and your own tokens. Don't install everything.

I need a distinct visual brand.

Consider native CSS, a utility workflow or headless components. The design system can be yours while interaction primitives remain shared.

Break it

Imagine adding three different libraries to build one navigation bar. How many competing naming conventions, styling resets and dependencies are you now maintaining?

Build it

Sketch one landing page as plain HTML/CSS, one with Bootstrap-style components and one with Tailwind-style utilities. Decide which approach is easiest to understand, deploy, adapt and maintain. Then move to how a static page becomes an app.
